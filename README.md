# 瞎掰大王 v0.6 · 512 道联机怪名题

原生微信小游戏 + 浏览器试玩 + Node.js 房间服务。无第三方 npm 依赖。

## 本次更新

- **512道好友联机题**：从64道扩至512道，新增448道，另有16道独立单人试玩题，共528道。保留王不留行、阿月浑子，加入螺子黛、袯襫、橐籥、藏钩、摄提、帝江等词条。每题附释义、解读、出处与备用假答案。
- 覆盖植物、动物、天文、礼俗、服饰、工艺、建筑、饮食、古代游戏、传说等23种内部题材。先排除全员已见题，再分散抽取题材；可用题材充足时，一局不会连出同一种题材。
- 56道《山海经》题明确标注古书语境，考的是传说形象，不宣称真实生物存在。一词多义的题目补充语境，避免拿另一个真实义项当作错误答案。
- 联机只抽取**房间内所有玩家都没见过的题**。记录关联玩家身份，换昵称、换房、再来一局、重启服务均保留。
- 发出第一题前先持久化整局题组；即使中途退出或服务中断，未展示的预留题也不回收，防止反复开局刷题。
- 新题不足时不允许开局，可改成短局；连3道都不足时需要补充新题。旧题不会循环。
- 大厅显示“全员未见 / 题库总量”和身份类型。同一玩家身份不能同时占据多个房间席位。
- 单人试玩按本机保存独立历史，最多5题一局，剩余不足5题时只玩剩余题，耗尽后停止。
- 增加可选的微信登录身份验证和严格登录模式，准备好 AppID、AppSecret 及服务器后可配置启用。

**记录从 v0.5 开始积累，无法追溯旧版本未保存的游玩历史。** 修改现有题目的措辞、解读或选项时保留原 `id`；真正新增的题目使用新 `id`，不能通过重命名 ID 把旧题重新发给玩家。

## 身份与避重范围

浏览器试玩默认是游客身份：凭证保存在 localStorage，历史保存在服务端。同一浏览器配置、同一服务地址下，刷新、重开页面、换昵称和换房不会改变身份。不同浏览器、无痕窗口、清除本地数据或改变服务地址可能形成新游客身份；游客模式不能识别现实中的同一个人。

配置并启用微信登录后，服务端向微信验证登录 code，按同一小游戏 AppID 下的 OpenID 归并记录，同一微信账号换设备也能继续避重。正式需要账号约束时，服务端必须设置 `REQUIRE_WECHAT_LOGIN=true`，避免从游客入口绕过。更换微信账号仍属于不同身份。

旧游客登录微信时会合并已有历史。AppSecret、session_key 和原始 OpenID 不返回客户端；持久化文件保存不可公开的身份凭证、哈希身份和题目 ID，不保存玩家答案。不能以避重功能保证杜绝查资料、场外交流等其他作弊方式。

## 已实现玩法

3～6人创建或加入六位码房间 → 全员准备 → 编假答案 → 选择并确认真相 → 票数、作者、真相逐步揭晓 → 计分与再来一局。猜对 +2 分，每骗到1人 +1 分；给别人的原创假答案送笑脸不影响胜负。支持并列冠军、复制战绩、好友分享、草稿保存、断线重连和掉线房主转移。

| 模式 | 轮数 | 编答案 | 猜真相 |
| --- | ---: | ---: | ---: |
| 闪电局 | 3 | 30秒 | 20秒 |
| 经典局 | 5 | 60秒 | 30秒 |
| 慢慢编 | 8 | 90秒 | 45秒 |

所有怪名题使用统一分类，避免标签提前泄底。联机题库只在服务端加载；真相揭晓前不发送答案标识、解读、来源标题或网址。单人公开题库与联机题库不重叠。

## 题库来源与后续扩充

新增词条参照[教育部重编国语辞典](https://language.moe.gov.tw/001/Upload/Files/site_content/M0001/respub/dict_reviseddict_download.html)及其[萌典镜像](https://www.moedict.tw/)核对，题面、短答案和解读为游戏重新编写的内容。原始词典资料及其许可归原权利人；项目不附带下载的整部词典。传说题依据公版古籍[《山海经》](https://zh.wikisource.org/zh-hans/山海經)编写，并保留各卷的出处链接。原64题保留逐题来源。

备用假答案是明确的游戏创作，仅在玩家未交卷时补位，不能作为知识资料。揭晓后应以真实答案及出处为准。题材信息只用于服务端调度，不提前发给玩家。

题库是有限的，512道不等于无限新题；每局3、5或8道，开局即消耗整组题。多人组队可用数量取决于全体成员历史的并集。后续可在 `server/packs/` 添加新题包，并在 `server/questions.js` 注册；按同一事物审查别名和近义题，不靠换写法增加题量。保留旧 ID 和玩家数据，新增题即可自动进入未见题池。

添加题目后运行 `npm run check:bank` 与 `npm test`。检查器会验证 ID、题目重复、选项长度及去重、出处、题材和传说语境；**语义正确性及同义别名仍需人工审核**。服务端题包不放进微信客户端发布包，也不作为 HTTP 静态资源提供。

## 本机与好友试玩

需要 Node.js 20 或更新版本。在项目目录运行 `npm start`，或在 macOS 双击 `启动本机试玩.command`。打开 `http://127.0.0.1:8765/preview.html`。

多人测试请使用3台设备，或独立浏览器配置；**同一浏览器开多个标签页会被视为同一个玩家，不能扮演多个参赛者**。房间令牌和输入草稿保存在当前标签页 sessionStorage，长期玩家凭证保存在 localStorage。主动退出房间不会清除玩家历史；关闭标签页前建议先退出房间。

同一 Wi-Fi 测试：停止原服务，运行 `npm run start:lan` 或双击 `启动同WiFi联机.command`。查看电脑的局域网IP，所有玩家从 `http://该IP:8765/preview.html` 进入。创建房间和邀请时统一使用这个地址，电脑保持开机。

双击 `preview.html` 的 `file:` 页面仅用于单人试玩；好友联机必须从运行中的 HTTP 服务打开。

## 玩家记录与升级

`npm start` 默认把记录写入 `data/players.json`，也可设置 `PLAYER_DATA_FILE=/固定目录/players.json`。首次启动会创建文件及目录。使用原子文件替换保存；写入失败则阻止发题，不降级为空历史。损坏的记录文件会阻止服务启动。同一文件仅允许一个服务进程使用，另一个进程不能覆盖历史。

升级代码时停止旧服务，保留并备份玩家记录，再启动新版本。部署目录变更时使用固定的 `PLAYER_DATA_FILE`。Docker 模板将 `/app/data` 挂载到持久卷。**不要删除玩家文件或数据卷来解决启动问题，否则会失去避重历史。** 玩家文件及其备份包含身份凭证，不要公开、提交到源码库或装入客户端发布包。

对局和成绩仍保存在进程内存：重启会结束现有房间，但已保存的玩家历史保留。已有客户端凭证不能被识别时会报错，不会悄悄重建空历史。服务只支持一个实例；多进程扩容需先迁移到共享、事务性的玩家和房间存储。

## 微信身份接入

1. 将目录作为小游戏项目导入微信开发者工具，将 `project.config.json` 的 `touristappid` 替换成自己的小游戏 AppID。
2. 服务端设置 `WX_APPID`、`WX_APPSECRET`，需要强制账号避重时设置 `REQUIRE_WECHAT_LOGIN=true`。
3. `config.js` 设置 `serverBase: 'https://你的域名'` 与 `useWechatLogin: true`。**AppSecret 只能放在服务端环境变量中。**
4. 在微信后台配置 request 合法域名；客户端通过 `wx.login` 获取 code，服务端向微信换取并验证身份。
5. 真机检查登录、跨设备同账号避重、键盘、分享、前后台切换、断线恢复和安全区域。

严格登录开启后，普通网页游客无法新建或加入房间。未配置服务器与微信账号前，当前本地试玩继续使用游客模式。本次只完成微信接入代码和模拟接口测试，尚未进行真实账号联调或上传体验版。

微信 API 参考：[小游戏 API 官方类型定义](https://github.com/wechat-miniprogram/minigame-api-typings)、[wx.login](https://developers.weixin.qq.com/minigame/dev/api/open-api/login/wx.login.html)。

## 房间与掉线规则

新玩家只能在大厅加入。主动退出后不能中途重入；短暂切换后台或同一标签页刷新可以恢复。15秒无心跳显示掉线，房主离线超过30秒会自动转给在线玩家；大厅房主可移除掉线席位。仅在本机退出的席位可能仍在服务端，需要原房主移除或等待房间过期才能以同一身份另开房间。

真相揭晓第3秒显示作者，第6秒显示真相并结算，第24秒自动继续；全员点继续可提前推进。对局中退出者保留已提交选项和成绩，未完成操作由超时机制处理。空房间会清理，一小时无有效访问的房间过期，玩家历史不随房间清理。

运行 `npm test`，当前62项测试通过。`npm run check:bank` 检查528道题的结构和限制。自动化覆盖单人与多人完整流程、计分、超时、操作重试、题目和出处保密、小屏点击、草稿恢复与投票确认，包括：

- 身份凭证保留、同身份多席位拦截、未知凭证不清空历史。
- 写盘失败不发题、历史损坏拒绝启动、进程锁保护。
- 微信验证失败处理、伪造 OpenID 拒绝、跨设备同账号归并及游客历史合并。
- 单人记录恢复、耗尽后停止、公开与联机题库不重叠。
- 原64题全部已见的玩家升级后恰好获得448道新题，旧记录不重置。
- 连续64次8题开局，512道题全部只预留一次，耗尽后拒绝开局。
- 多题材分散抽取、某类耗尽后的自然补齐，以及题材元数据不泄露。
- 新增服务端 JSON 题包及维护脚本不能通过 HTTP 下载。

本版在真实浏览器复用原试玩身份和玩家文件，验证升级后显示507 / 512道未见，原有5道记录保留。此前已验证六人大厅、开局及换房保留历史；测试同伴由独立 HTTP 客户端模拟。微信真机、跨设备 Wi-Fi、Docker 构建和公网部署尚未实测。部署模板见 [deploy/README.md](deploy/README.md)。当前用于好友内测，公开运营还需完善内容审核、举报及运营支持；输入长度与字符过滤不能替代内容审核。

## 主要文件

- `game.js`、`config.js`：微信入口及登录配置。
- `src/app.js`、`src/engine.js`、`src/questions.js`：单人界面、逻辑与16道题。
- `src/room-ui.js`、`src/client.js`：联机界面、身份缓存、同步与重连。
- `server/rooms.js`、`server/index.js`：房间裁判与 HTTP 服务。
- `server/players.js`、`server/wechat.js`：持久历史与微信身份验证。
- `server/questions.js`、`server/packs/`：512道联机题、稳定 ID、内部题材、备用假答案和出处。
- `scripts/check-bank.js`：题库结构检查器。
- `deploy/`、`Dockerfile`：单台服务器部署模板。
- `tests/`：自动化验证。
